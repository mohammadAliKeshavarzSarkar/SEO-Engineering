# TS04.2 — Pilot workspace and review preparation

Status: offline staging and artifact plumbing; no model execution or actual independent reviewer judgments. Use a clean exact source checkout, outside the agent workspace. This is a development pilot only.

## Operator workflow

1. Freeze an actual model/runtime, settings, equal budget, 16-case cohort, common UTF-8 context file, complete-toolkit treatment and candidate archive SHA-256. Keep the source checkout, controller, private suite/rubrics, receipts and ledger inaccessible to the agent. Use the [trial controller](trial-control.md) to schedule. Do not use placeholder configuration.
2. For each slot, create a new target root outside the source checkout with `python scripts/prepare_trial.py stage --suite evaluations/cases.json --control /private/control.json --blind-id RUN_ID --archive /private/skill.zip --context /private/context.txt --target /isolated/new-project --out /private/staging-receipt.json`. The source checkout must be clean and its HEAD must match config. Both arms get identical context.txt; treatment gets source-matched skill files under .agents/skills; public pilot omits the entire evaluation subtree, including cases.json. Baseline gets no skill. No other source content is copied. This omission changes the candidate and may cause missing documentation links; it is intentional, not a full portable acceptance experiment. Held-out uses an unmodified candidate. Instruction-only comparisons require a separately matched tooling setup and are not supported by this staging command.
3. Verify restrictions with the actual runtime: fresh account/session context, no global skills in baseline, no inherited memories or unrelated connectors, no access to parent paths, rubric files, network or other trial workspaces. The stager does not enforce these permissions or guarantee that public answers are absent from model training or other documents. It records what it staged, not what the model could access. Treat contamination as a deviation or invalid trial, not an agent failure. Verify discovery and actual resource use separately. Give only the dispatched task and shared context, never the controller or arm comparison. Record actual version, tool/settings, session and environment references, order and deviations.
4. Init ledger with `python scripts/prepare_trial.py init-ledger --suite evaluations/cases.json --control /private/control.json --out /private/ledger.json`. Every slot starts not_started. Update only from observed execution; use unique actual session refs. Keep failed/partial outputs and traces when available. No retries replacing failures.
5. Store sanitized nonempty UTF-8 response and trace files in a separate **dedicated, fresh** private artifact root using exactly RUN_ID/output.txt and RUN_ID/trace.txt; no symbolic links. Hash actual bytes. Incomplete slots can have optional artifact pairs. Each file limited to 16 MiB; oversized files require separately reviewed handling. Use `verify-artifacts --suite ... --control ... --ledger ... --artifacts /private/artifacts --out /private/artifact-check.json`. Fixed refs, actual file hashes, and the full artifact-root inventory are checked; unrecorded files, stray slot directories, nested paths and symlinks fail validation rather than being silently ignored. Empty directories for known slots without captured evidence are allowed. Record any unexpected evidence in the private incident review and reconcile the ledger from observed outcomes without silently deleting or suppressing evidence; use a separately reviewed fresh root if correction is required. Identical content is not evidence of independent sessions. Parent paths must be trusted and stable. No artifact bytes are uploaded.
6. Use `python scripts/prepare_trial.py blind --suite evaluations/cases.json --control /private/control.json --ledger /private/ledger.json --artifacts /private/artifacts --out /private/packet.json` instead of the earlier metadata-only command. Give reviewers only packet and sanitized artifacts. The tool verifies bytes before packet creation, not actual model provenance. Keep control and ledger private. Inspect response/trace content for arm-revealing details before grading; record imperfect blinding.
7. Have two independent reviewers grade a small separate calibration sample with known criteria, then discuss discrepancies before pilot grading. Use real reviewer assignments and preserve original judgments. No model self-grading. `python scripts/prepare_trial.py compare-reviewers --packet /private/packet.json --first /private/grades-a.json --second /private/grades-b.json --out /private/agreement.json` compares independently supplied grades by criterion, identifies missing overlap and disagreements. It measures observed agreement, not truth or reviewer independence. Adjudicate disagreements separately; do not discard negative evidence. Use the maintainer-only completed adjudication integrity checker described in maintainer-only source procedure `operations/ts09-pilot-handoff.md` (not in the portable skill) to compare the two original graded packets with the exact final adjudicated grade packet, preserving unresolved/missing coverage and any original observed disqualifier. Record explicit separate resolutions for disagreement criteria; a matching final score is not evidence of independence.
8. Use `python scripts/prepare_trial.py finalize --suite evaluations/cases.json --control /private/control.json --ledger /private/ledger.json --artifacts /private/artifacts --grades /private/adjudicated.json --out /private/report.json` to repeat actual artifact checks then score. No automatic release or performance claim.

## Pilot launch gate

Freeze source/package, real model/runtime settings, permission and isolation evidence, actual activation check, public rubric restrictions, equal budgets and independently calibrated reviewers before launching. For this pilot choose descriptive paired outcomes, zero observed skill critical failures as a safety guardrail, and inspect every baseline-only pass; no effectiveness claim from a small known cohort. Full public and separate held-out cohorts remain required. Actual trial records must stay private, not in CI or public skill.

CI stages only two fictional paired workspaces from the source-matched archive, checks identical context and evaluation omission, initializes not-started ledger and runs synthetic unit tests. It does not invoke an agent, validate an actual sandbox or generate performance results.

## Incomplete-run safety review (TS07.6)

Normal blind grading includes completed slots only. Before making a pilot safety or continuation decision, separately review every incomplete, timeout and error slot, including available partial output or trace, using the maintainer-only [instruction evaluation review](../docs/08-learning/instruction-evaluation.md) for methodology and the source-side operator procedure in operations. Keep both reports bound to the same frozen ledger. Unstarted slots remain unexecuted; an unavailable artifact or partial trace cannot prove absence of harmful behavior. Never add a partial run to the normal completed scoring packet or silently replace it. Preserve all observed adverse signals, including those outside the case rubric, in restricted incident records. Actual operator independence and isolation must still be verified.
