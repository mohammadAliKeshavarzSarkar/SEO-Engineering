# Integrated research pipeline (R01–R10)

Read-only research by default. For a narrow task select necessary stages only; document skipped stages. Use the [run manifest](../templates/research-run-manifest.md) and [R10 procedure](../docs/02-research/r10-research-automation-and-validation.md).

| Stage | Required input | Output | Review gate |
|---|---|---|---|
| R01 | Authorized scope, actual offering | Audience/task/goal map | Legitimate fit and owner |
| R09 cross-cutting | Language, market, availability | Locale register | Actual scope and lawful evidence |
| R02 | Native seeds, permitted sources | Raw observations | Provenance, units, missingness |
| R03 | Comparable observations | Task assessments | Confidence and alternative meanings |
| R04 | Raw queries, reviewed scopes and intent | Candidate groups | Every pair and protected distinctions reviewed |
| R05 | Relevant tasks and comparators | Benchmark and gap candidates | Comparable evidence, original contribution |
| R06 | Reviewed tasks, page inventory | Registry and map | Existing useful pages preserved; ownership not canonical |
| R07 | Page registry and link evidence | Coverage, edge and lifecycle plans | Actual user value and observed vs proposed edges |
| R08 | Defects, opportunities, estimates, dependencies | Triage and reviewed backlog | Critical repairs first; approval separate |
| R10 throughout | Versioned artifacts, evidence and decisions | Validation and run record | Integrity, review, unknowns and reproducibility |

Prepare module-specific inputs from reviewed records, preserving original IDs and source pointers. See each module for its exact tool input contract; no automatic conversion between CSV and JSON or between tools is implied. Use deterministic utilities only for their stated scope. Tool output requires interpretation and review. If a required input is missing, record blocked/provisional; do not synthesize evidence. Escalate credible critical harm immediately. Preserve actual data, sanitized artifacts and history privately; do not store them in the skill repository.

Final deliverable: scope and evidence registry, proposed page tasks, content and technical requirements, prioritized backlog, acceptance tests, blockers and next checks. Implementation is a separate authorized mode; use [new website workflow](new-website.md) and release checks. A valid handoff does not establish live index status or rankings.

For new detailed SERP records prefer the R03 snapshot/results-v2 contract; legacy flat observations can be retained as limited evidence. For stage handoff review consult the [knowledge consistency guide](../docs/01-foundations/knowledge-consistency.md). Do not map a strategic page owner directly into an HTTP canonical assertion or a provider observation into a T11/T12 acceptance decision.
