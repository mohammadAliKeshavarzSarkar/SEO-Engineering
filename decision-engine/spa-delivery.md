# SPA delivery decision protocol

Use [T03](../docs/03-technical/t03-react-vite-spa.md) after [T01](../docs/03-technical/t01-architecture-detection.md) and [T02](../docs/03-technical/t02-javascript-rendering.md): inspect actual router mode, concrete route registry, generation, deployment, and public base. Do not infer delivery from React or Vite dependencies. Retain a verified working CSR/SSG/SSR route when justified. If direct entry fails, check host routing first; missing assets and API errors must not become shell 200. If initial or ready content differs, investigate data/hydration and metadata owner; distinguish unknown render from absence. If selected static build omits concrete dynamic/locale paths, repair enumeration and output, not URL strategy by default. If protected routes are involved, preserve auth and do not serialize private payloads into public build. When host cannot return accurate not-found status, document alternatives and limits; JS error UI does not alter HTTP status. Consider selective prerender/SSR only for verified needs, compatible versions and approved host/runtime. Preserve existing useful navigation, accessible UI, URLs, scope, and rollback. Apply [SPA patterns](../implementation-patterns/react-vite-spa.md), [route delivery](../implementation-patterns/route-delivery.md), local artifact checks and actual host/browser verification separately. Output reviewed alternatives, evidence, smallest correction, test criteria and limitations. Provider-independent; no dependency on a live crawler or pending contract.
