# Index and canonical decision protocol

Use [T06](../docs/03-technical/t06-indexing-canonicals.md). Establish intent, equivalence, scope, current observations and actual processed evidence separately. If protected exposure is suspected, escalate and preserve access controls. If intended representative is blocked/noindex/wrong status, repair actual owner narrowly; do not remove legitimate exclusions. If alternative canonical selected, compare useful content, actual declarations, redirect/link/sitemap and last crawl vs release. A valid duplicate exclusion may be desirable. If canonical targets conflict, resolve owner and equivalence before choosing a direct accessible representative; don't merge distinct locale/parameter/pagination content blindly. If evidence incomplete or pre-change, defer current search verdict, verify live change and monitor actual processed evidence separately. For soft 404 inspect body and real status; do not label engine classification from a local test. Avoid repeated submissions, unsupported Indexing API use or blanket index changes. No-change valid. Use [patterns](../implementation-patterns/index-canonical.md), reviewed scope, concrete assertions, rollback, and actual search measurement separately.
