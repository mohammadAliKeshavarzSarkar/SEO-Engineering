# Topical architecture and content lifecycle decisions

Use [R07](../docs/02-research/r07-content-gaps-and-topical-architecture.md) after R06 and before R08. Read-only by default.

| Condition | Decision |
|---|---|
| Useful existing page has adequate task coverage and reachability | Keep and maintain |
| Relevant task incompletely served | Enrich existing page if independently useful |
| Useful public page not reachable in observed graph | Check inventory, actual link form and scope; propose contextual path if verified |
| Disconnected cluster with local inbound links | Investigate path from meaningful entry, not just link counts |
| Broad user need for overview or browse | Evaluate useful hub; compare flat navigation or existing category |
| New independent task with real evidence and supported offering | Propose page or tool with brief, links and owner |
| Uncertain/partial inventory | Mark candidate gaps, verify before changing |
| Duplicate task or obsolete page | Review differentiation/retirement through R06 with migration approval |
| Distinct valuable low-traffic content | Preserve unless independently justified |
| Unsupported content or mass generation for ranking | Reject or defer |

Require user task, evidence, own inventory, useful contribution, alternatives, planned edges, scope/owner, accessibility, approval, tests, outcome and maintenance. Do not mistake semantic topic relationships for observed links, or orphan candidates for live indexing failures. No automatic page creation, redirects, deletion or sitewide keyword anchors.

Use [coverage matrix](../templates/topic-task-coverage.csv), [link plan](../templates/internal-link-plan.csv), [lifecycle record](../templates/content-lifecycle.csv) and [page mapping protocol](page-mapping.md).
