# Performance decision protocol

Use [T09](../docs/03-technical/t09-performance.md). Establish actual user journey, field provider/aggregation/device/window, lab profile and UX constraints. Do not infer URL field health from origin data, INP from TBT or good metrics from missing values. If field problem observed, reproduce representative bottleneck under authorized lab conditions. For LCP identify actual element and delay phases; for INP identify actual interaction and input/processing/presentation delay; for CLS inspect actual shifts including post-load. Choose smallest targeted correction, preserve primary content, meaningful interaction, animation, localization, security, consent and accessible reduced motion. Do not impose a score-100 target, blanket motion removal or public personalized cache. If evidence mismatched/incomplete, defer comparison and preserve failures; use fixed profile, predeclared budget and repeated runs. Verify actual design/task acceptance and comparable lab evidence before release, field window outcome separately. No-change valid. Use [patterns](../implementation-patterns/performance-optimization.md) and owner-approved rollback. No live collection requirement.
