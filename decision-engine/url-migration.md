# URL and migration decision protocol

Use [T07](../docs/03-technical/t07-url-migrations.md). Establish approved scope and old/new content registry first. If useful URLs can be retained, prefer no visible URL change. For a genuine move, map exact old identities to reviewed equivalent or consolidated replacements, not arbitrary close strings. Separate retain, permanent, temporary, remove, unknown; protected/access/action endpoints require separate review. Preserve functional query and locale semantics and approved attribution; no blanket sorting/decoding or automatic Persian slug translation. Review planned graph and actual host precedence; prefer direct final redirects, do not confuse 304 with redirect. Unknown/unvisited targets defer conclusions. No unapproved destination fetch, open redirect or untrusted Host. Align destination links/canonical/hreflang/sitemap and actual content/status. Verify matched GET traces separately from index outcomes, set owner-approved rollback and monitor both origins. Change of Address only where eligible and explicitly authorized. Use [patterns](../implementation-patterns/url-migration.md), retain evidence and stop unsafe release. No-change valid, no ranking guarantee.
