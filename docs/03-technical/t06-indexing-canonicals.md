# T06 — Indexing and canonical engineering

Status: initial methodology and local evidence QA, no live search inspection, network, submission or independent behavioral evaluation. Selected primary sources reviewed 2026-11-18. Use [T05](t05-crawling-robots.md), [T02](t02-javascript-rendering.md) and [R06 page mapping](../02-research/r06-keyword-to-page-mapping.md).

## WHAT
Investigate intended index eligibility and representative URL selection independently of actual search-engine processing. Distinguish strategic page ownership, duplicate equivalence, declared canonical preference, redirect destinations, observed signals and engine-selected canonical. A page can be technically eligible without being indexed or ranking. A duplicate excluded in favor of the intended representative can be healthy.

## WHY
Unintended noindex, wrong status, conflicting declarations, weak discovery, empty content or duplicate representations can impair intended search acquisition. Historical index evidence can predate a repair. Changing every canonical, requesting indexing repeatedly or reporting all excluded URLs as errors may create new regressions. Work by meaningful route/template cohorts and verified causes.

## WHEN / WHEN NOT
Use for intended public pages missing from an index, selected-canonical disagreement, duplicate variants, unintended exclusions, harmful status/content changes or planned consolidation. If a useful representative is selected and aliases intentionally excluded, retain that behavior. Do not force every URL to be indexed. No access bypass, public exposure of protected data, mass submissions, invented inspection data or website writes without appropriate permission.

## INPUTS
Reviewed strategic page registry, concrete URL and intended purpose, duplicate equivalence evidence, preferred representative, scope/property/engine, exact current request/profile, redirects/status, robots applicability, header/source/rendered declarations, actual content and links, sitemap, timestamps and release/change markers, separate authorized processed inspection result (including last crawl, user-declared and engine-selected canonical and reason/verdict), coverage and limitations. Preserve original malformed/duplicate tags and actual evidence separately; never equate a URL hash, matching title or similar query with semantic equivalence.

## HOW

### 1. Build intended identity inventory
Assign reviewed purpose: intended representative, duplicate variant, intentionally excluded, protected, unknown. For each useful independently maintained page retain intended primary URL; avoid collapsing distinct products, languages, pagination, filters or tasks just because string similarity is high. R06 ownership is planning, not automatically canonical selection. Compare meaningful primary content, user task, locale, access and lifecycle before grouping. A parameter may change content; don't strip it blindly. URL normalization must be explicit and policy-versioned. A self-referencing canonical is a useful project convention, not an absolute search eligibility rule.

### 2. Inspect current eligibility separately from processed state
Check actual requested/final response and redirect chain (T07), robots permission (T05), applicable HTTP X-Robots-Tag and source/rendered robots meta (T02), content type, meaningful primary content and required resources, discovery/link evidence, sitemap and canonical declarations. Noindex requires crawler access; don't expose protected content to make directives visible. Intended exclusions are not automatically bugs. Preserve raw directives and user-agent specificity; don't assume all agents share policies. Google resolves conflicting applicable robots rules conservatively, applying the more restrictive rule. Inspect all applicable declarations, not just the last. Google also honors body robots meta, while HTML canonical annotations need valid head placement. Distinguish local markup checks from crawler interpretation. Non-HTML resources can use X-Robots-Tag; crawler access is still necessary. Avoid using noindex to make Google select a preferred canonical. A 200 response is not proof of useful content. A live test may indicate accessible current response, not indexing or selected canonical.

### 3. Reconcile canonical signals
Google describes redirects and canonical link annotations as strong preference signals, sitemap inclusion as weaker. Signals can reinforce each other; no numeric weights or guarantees. Use redirect when a duplicate URL need not remain available and a true replacement exists; use canonical annotations for equivalent or very similar pages that remain available. Use actual 404/410 for genuinely removed content with no replacement; preserve temporary outages and deliberate utility paths appropriately. Align internal anchors, sitemap, actual redirects and intended canonical. Use absolute resolved URL preferences from trusted configuration; avoid conflicting header/HTML/rendered tags, malformed targets, fragments and different language targets without reviewed justification. For non-HTML documents an applicable HTTP Link canonical can be useful. Do not make distinct content duplicates by declaring one target. A search engine may select differently; assess content and signals, not forced directives.

Review each declared target's actual status, access, intended eligibility and content equivalence. Prefer direct final intended representative rather than chains, cycles, redirects or blocked/noindex targets. Missing target data is not evidence of a broken target. Cross-origin targets require explicit scope/authority for inspection and real equivalence; do not automatically fetch them. Separate source/header/rendered declarations, preserve duplicate and malformed values and resolve URLs according to actual context; use T02 for matched readiness. A chain/cycle in supplied declarations is a review finding, not Google's chosen graph. Ordinary duplicate content is not automatically spam. Don't set all canonicals to home or collapse useful language/pagination variants; use R09 and T07.

### 4. Interpret Search Console evidence
Use authorized property with least privilege. Record exact inspected URL, property, retrieval timestamp, last crawl, reason, crawling/indexing state, declared and Google-selected canonical, platform evidence ref and whether indexed data or live test. URL Inspection indexed view is historical processed evidence; live test cannot predict selected canonical. Google URL Inspection API exposes indexed-version evidence, not live inspection or an index request API. Preserve original API fields and unknowns, never turn HTTP 200 API transport success into indexed state. The Page indexing report is aggregate/reported coverage, with limited examples; not a complete inventory or current per-URL verdict. Select representative affected and unaffected templates, route intents and prior comparable cohorts. Distinguish observed last crawl before a release from inspection retrieval after release; even a crawl at/after release does not prove the new revision was processed (caches, rollout and variants). Use latest applicable exact evidence and don't erase earlier records.

| Reported state / symptom | Investigation, not automatic repair |
|---|---|
| Discovered – currently not indexed | Discovery, host availability, actual crawl/log evidence, URL family and useful links; do not infer fixed budget |
| Crawled – currently not indexed | Actual delivered content, render, duplicate equivalence, intended canonical, usefulness; no single assumed cause |
| Duplicate, Google chose different canonical | Compare intended vs selected URL, equivalence, all signals and processed recency |
| Alternate page with proper canonical | Often intended; check representative and user need before changing |
| Excluded by noindex / blocked by robots | Compare intended policy and actual visibility/access |
| Soft 404 | Inspect actual status and meaningful content/error UI; distinguish suspected from reported classification |
| Page with redirect / not found | Expected for moved/removed URLs; verify intended target or absence |
| Server error / access failure | Investigate delivery, availability, scope and recovery |
| Live test looks good but indexed record stale | Verify new revision and monitor actual processed state; don't claim resolved yet |

Never diagnose penalty from a status alone. Check authorized manual actions/security reports and content quality where relevant. Do not use site: searches as an exhaustive census. Separate technical eligibility, processed index state and performance.

### 5. Repair and verify selectively
Correct actual owner: deployment/status, route metadata, directives, generator registry, link navigation, sitemap or meaningful content. Keep intentional noindex, legitimate redirects, protected access and useful distinct URLs. If duplicate consolidation is approved, align signals and actual destination, retain meaningful query/locale behavior and plan rollback. A temporary outage should not trigger permanent exclusion or bulk deletion. If current technical correction is verified, track separately from search processing. Use authorized sitemap submission for large URL sets and selected URL Inspection requests where appropriate; repeated submissions are not a speed guarantee. Google Indexing API eligibility is restricted to pages with JobPosting or BroadcastEvent within VideoObject; notification does not prove indexing; do not use it to submit ordinary articles/products or fabricate qualifying markup. No unauthorized submissions or removal requests. Requests/notifications are not completed indexing. Use documented platform permissions and quotas; monitor rather than promise indexing deadlines.

### 6. Offline local evidence QA
Use scripts/audit_index_evidence.py, a local projection, not WebsiteBotScroll schema. Envelope schema_version "1", scope, urls (1–5000 unique ids and exact URLs). Row: id, url, intent (representative/duplicate/excluded/protected/unknown), preferred_url absolute HTTP(S) or null (representative self/null), changed_at UTC timestamp/null, current object, processed object/null. Current: status complete/partial/failed/not_collected, evidence_ref and observed_at required for attempted capture (null if not collected), http_status integer/null, robots allowed/disallowed/unknown (reviewed applicable policy), http_noindex/initial_noindex/rendered_noindex/sitemap_member bool/null, source_canonicals/header_canonicals/rendered_canonicals array of resolved reviewed absolute HTTP(S) URLs or null. Repeated declarations retained; null = unknown/uncollected, empty array = assessed absence (only treat as conclusive with complete group). Preserve malformed/raw declarations separately, mark affected group unknown/partial rather than invent normalized values. URLs compared literally; no normalization, credential or fragment URLs rejected. No automatic equivalence from matches. Failed/uncollected response fields null, but independent sitemap/robots evidence may be known. Capture status summarizes relevant response/extraction; use separate evidence refs within the underlying reviewed record. Supply only aligned source/full-response/rendered values, or null/partial if mismatch. Processed: evidence_ref, property, retrieved_at, last_crawl_at UTC/null, state indexed/not_indexed/unknown, user_canonical/selected_canonical reviewed absolute URLs/null. All timestamps exact UTC YYYY-MM-DDTHH:MM:SSZ. Map processed state only from actual authorized indexed-view evidence, not live status or raw API transport. Verify property/URL/crawler/profile/revision scope externally; tool trusts supplied reviewed reference and does not query index. Change timestamp is reviewed relevant release; comparison only labels recency, not proof of revision. Retain old processed state in input/evidence; defer current verdict when recency unknown or pre-change.

Flags: intent/status/directive/robots discrepancy, conflicting/repeated canonical targets, preference mismatch, sitemap policy review, processed mismatch with last crawl at/after declared change, target response/directive issues and chains/cycles. Graph edges only for complete status-200 records with all canonical groups available and one unique non-self target, so incomplete/conflicting records never imply a graph edge. Targets outside supplied inventory deferred. Positive observed conflicts may be reviewable even with partial evidence; no definitive absence or index eligibility verdict. No canonical required by universal rule; local project preferences can be checked separately. Script does not test content equivalence, parse HTML/headers, access, robots, URL resolution, sitemap or search API. New output filename required; exit zero means processing succeeded. See [fixture](../../examples/index-evidence/README.md).

## VERIFY
Use reviewed URLs representing each purpose and locale; confirm actual HTTP/redirect status, accessible content, directive applicability, source/head/header and ready DOM, actual canonical target, link/sitemap alignment and absence of unintended exclusions. Validate distinct content and protected access separately, never by noindex. Record current technical acceptance and later processed observation separately, with last crawl/retrieval and change time. If no processed evidence, explicitly pending. Compare matched cohorts and preserve unknown/unvisited records. Approval required for actual indexing/submission actions. E59–E62 are public scenarios, not measured agent outcomes.

## MEASURE
Track intended representative cohort with explicit denominator, sampled current conflicts, deferred/uninspected records, reported indexed/selected matching status with inspection time/property, exclusions by intended/unexpected reason, meaningful clicks/impressions and conversions separately. No site-wide inference from samples or treating declining indexed duplicate count as failure. Annotate releases and measurement lag. Monitor actual processed changes without promising recrawl/index timing.

## ADAPT
SPA: use T02/T03 matched readiness and true status/metadata evidence. Next.js: use full response and streaming/cache context T04. Multilingual: preserve local representatives and verified alternates (R09). Ecommerce/facets: keep genuinely useful distinct intent and pagination; don't consolidate all parameters. Small site: inspect important representative sample before broad changes. Large site: bounded cohorts and trusted logs/property data. No Search Console access: state current technical evidence only, actual index unknown. External canonical: review authority and equivalence without expanding network scope.

## RECOVER
If release introduces unintended exclusions, wrong status or broad canonical collapse, stop rollout and restore smallest approved prior behavior, recheck actual source/DOM/headers and representative inventory. For privacy exposure stop and escalate; noindex not access control. If processed state remains old, record lag and verify again under approved workflow; never claim recovery solely from live test. Do not change a verified good route merely to force different search selection. Preserve evidence and rollback.

## EXTERNAL PROVIDER EVIDENCE REQUIREMENTS
Optional approved WebsiteBotScroll provider may supply actual requested/final URL, redirect transactions/status, scoped robots decisions, repeated headers, raw/resolved source/rendered canonical and robots declarations with applicability and status, content observations, links, sitemap, capture times/version and limitations. It must not infer Google-selected canonical or actual index state from a crawl. Authorized processed Search Console evidence is a separately sourced record, not a live crawl observation; retain property/retrieval/last crawl and raw status. Strategic intended identity/equivalence remains project input. No external schema mapping until agreed; no duplicate collection, API or MCP.
