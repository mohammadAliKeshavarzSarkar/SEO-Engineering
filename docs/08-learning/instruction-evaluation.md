# Instruction evaluation boundaries

Use for authorized maintainer/operator evaluation, not ordinary target work or as guidance for a trial participant. The public synthetic cases and educational examples are known to authors; they cannot establish independent generalization. Keep independently authored held-out prompts/rubrics outside the public package.

## Distinct evidence layers

| Dimension | Actual evidence required |
|---|---|
| Entry and hierarchy | Actual runtime discovery/activation and permitted actions in a fresh session |
| Routing | Observed reference reads and independently reviewed relevance, missing dependencies, unnecessary reads |
| Context efficiency | Provider-reported tokens/cost/time when available, with exact settings and coverage; observed full/section reads and repeated reads separately |
| Multi-module reasoning | Response and trace evidence of applicable scope, contradictions, hard prerequisites, held actions and independent escalation |
| Deliverable quality | Independently reviewed relevance, evidence fidelity, actionable recommendations, actual completion boundaries and proportionality |
| Safety | Both complete and incomplete session evidence, permission anomalies, unobservable failures and owner disposition |

Structural tests and static byte estimates establish only their stated properties. Self-reported module IDs or a claimed file read are not proof of actual retrieval. A trace can be incomplete. Record unknowns rather than fabricate counts or infer token usage from file size. Compare matched runtime settings and task contexts using the existing controlled benchmark protocol; preserve frozen candidates and never revise a planned cohort after seeing results.

## Incomplete sessions

A timeout, error or interrupted session can contain unsafe action, material exposure, unsupported claims or attempted rubric lookup. Preserve available output and trace privately even without a final response. Review case disqualifiers and any additional incident evidence separately from completed-run grades. Distinguish observed adverse evidence, no signal in available partial evidence, and not observable. Absence of a signal in partial evidence is not clearance. If evidence is unavailable, keep the slot incomplete and the safety question unresolved. Escalate actual adverse signals; do not replace failed slots. Review every planned slot, including unstarted slots, before interpreting coverage. A completed normal grading report does not establish real runtime safety or reviewer independence.

No actual agent behavior has been measured by this guide. Use the existing [evaluation protocol](../../evaluations/benchmark-protocol.md) and [pilot execution procedure](../../evaluations/pilot-execution.md) as operator resources. No model invocation, new scoring rule or release authorization is supplied.
